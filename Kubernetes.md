# Конспект по Kubernetes (K8s)

## 1. Зачем нужен Kubernetes
*   **Проблема:** При масштабировании приложения до десятков и сотен Docker-контейнеров управлять ими вручную, следить за их доступностью и распределять нагрузку становится невозможно.
*   **Решение:** **Kubernetes (K8s)** — это открытая платформа для автоматизации развертывания, масштабирования и управления контейнеризированными приложениями.
*   **Основные функции:**
    *   **Самолечение (Self-healing):** Перезапускает упавшие контейнеры, заменяет и завершает их, если узлы не отвечают.
    *   **Балансировка нагрузки:** K8s может распределять сетевой трафик, чтобы обеспечить стабильность развертывания.
    *   **Автомасштабирование:** Увеличение или уменьшение количества контейнеров в зависимости от нагрузки.
    *   **Оркестрация хранилища:** Автоматическое монтирование выбранной системы хранения (локальной, облачной).

## 2. Архитектура Kubernetes
Архитектура делится на две основные части: **Control Plane** (панель управления) и **Worker Nodes** (рабочие узлы).

### Control Plane (Мастер-нода)
Управляет всем кластером и принимает глобальные решения:
*   **kube-apiserver:** «Ворота» кластера. Главный компонент, который принимает все REST-запросы (например, от `kubectl`).
*   **etcd:** Высоконадежное хранилище данных в формате «ключ-значение». Хранит всю конфигурацию и текущее состояние кластера.
*   **kube-scheduler:** Ищет новые Поды, у которых не назначен рабочий узел, и выбирает для них наиболее подходящую ноду.
*   **kube-controller-manager:** Запускает процессы контроллеров, которые следят за состоянием кластера (например, поддерживают нужное количество реплик Подов).

### Worker Nodes (Рабочие узлы)
Запускают и поддерживают работу ваших контейнеров:
*   **kubelet:** Агент, работающий на каждом рабочем узле. Он следит за тем, чтобы контейнеры были запущены в Поде и работали корректно согласно инструкциям.
*   **kube-proxy:** Сетевой прокси, обеспечивающий сетевые правила на узлах и перенаправление трафика (связь между Подами и внешним миром).
*   **Container Runtime:** Среда выполнения контейнеров (например, Docker, containerd, CRI-O), которая непосредственно запускает код.

## 3. Базовые абстракции: Pod, Deployment, Service

### Pod (Под)
*   **Что это:** Самая маленькая и базовая неделимая единица в K8s.
*   **Особенности:** Представляет собой один или группу контейнеров (например, контейнер с приложением + контейнер-логгер), которые делят между собой один сетевой стек (IP-адрес) и общие хранилища. Поды эфемерны (могут умирать и заменяться новыми с другими IP).

### Deployment (Деплоймент)
*   **Что это:** Контроллер, декларативно описывающий желаемое состояние для группы Подов.
*   **Особенности:** Вы указываете, какой образ использовать и сколько копий (реплик) должно быть запущено. Deployment сам следит за обновлением приложений без простоев (Rolling Update) и восстанавливает Поды в случае сбоя.

### Service (Сервис)
*   **Что это:** Абстракция, которая определяет логический набор Подов и политику доступа к ним.
*   **Особенности:** Так как у Подов постоянно меняются IP-адреса, Service предоставляет единый стабильный IP-адрес и DNS-имя, балансируя трафик между целевыми Подами.

## 4. Конфигурация: ConfigMap, Secret, Namespace

### ConfigMap
*   **Назначение:** Используется для хранения неконфиденциальных данных в формате ключ-значение (переменные окружения, файлы конфигурации, порты). Позволяет разделять конфигурацию от кода образов.

### Secret
*   **Назначение:** Похож на ConfigMap, но предназначен для хранения конфиденциальной информации (пароли, токены, SSH-ключи, сертификаты). По умолчанию данные кодируются в формате Base64 (обратите внимание: Base64 — это кодирование, а не шифрование).

### Namespace (Пространство имен)
*   **Назначение:** Виртуальная изоляция ресурсов внутри одного физического кластера K8s. Используется для разделения сред (например, `dev`, `stage`, `prod`) или распределения ресурсов между разными командами.

## 5. Kubernetes: попробуй сам (Практика)
Для локальных тестов и обучения используются легковесные утилиты:
*   **Инструменты для локального кластера:** `minikube`, `kind` или `k3s`. Они позволяют развернуть полноценный K8s прямо на рабочем компьютере внутри Docker или виртуалки.
*   **kubectl:** Главная консольная утилита для управления кластером K8s.
*   **Основные CLI команды:**
    *   `kubectl cluster-info` — проверка статуса кластера.
    *   `kubectl get nodes` — посмотреть список всех узлов.
    *   `kubectl get pods` — увидеть запущенные Поды.
    *   `kubectl apply -f deployment.yaml` — применить манифест конфигурации.
    *   `kubectl logs <pod-name>` — посмотреть логи конкретного Пода.

## 6. Когда Kubernetes НЕ нужен
Хотя Kubernetes очень популярен, внедрять его стоит не всегда. K8s **не нужен**, если:
1.  **Простая архитектура:** У вас небольшое монолитное приложение или проект состоит всего из 1–3 контейнеров. Достаточно обычного `docker-compose` или Docker Swarm.
2.  **Маленькая команда / Нет экспертизы:** K8s требует сложной настройки, поддержки и наличия DevOps-инженеров. Стоимость поддержки инфраструктуры может превысить пользу.
3.  **Статичная нагрузка:** Если приложение не требует частого масштабирования, динамического перераспределения ресурсов и частых релизов.
4.  **Жесткие ограничения по бюджету:** Для работы Control Plane требуются дополнительные серверные ресурсы, что увеличивает затраты на инфраструктуру на начальном этапе.
