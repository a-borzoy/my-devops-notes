## 1. Проблемы ручного деплоя
До появления CI/CD разработчики и сисадмины переносили код на сервера вручную. Это вызывало множество проблем:
* **Человеческий фактор (Ошибки ввода):** Легко опечататься в названии папки, забыть пробросить порт в команде `docker run` или залить не ту версию файла.
* **Проблема "На моей машине всё работает":** Код отлично запускается на ПК разработчика, но падает на сервере из-за разницы в версиях операционной системы, Python/Node.js или отсутствующих библиотек.
* **Огромные траты времени:** Ручной запуск тестов, ручная сборка Docker-образов через `docker build` и копирование файлов занимают часы, которые можно потратить на написание кода.
* **Долгий поиск багов:** Если релиз сломался, приходится вручную перебирать историю, чтобы понять, какой именно коммит и когда разрушил сервер.

## 2. Анатомия пайплайна
**Пайплайн (Pipeline — трубопровод/конвейер)** — это автоматизированная последовательность шагов, которую проходит код от момента сохранения разработчиком до запуска на сервере.

### Основные понятия:
* **Stage (Стадия/Этап):** Логический шаг конвейера. Стадии выполняются строго по очереди. Если одна стадия падает, весь конвейер останавливается.
* **Job (Задача/Джоба):** Конкретное действие внутри стадии. На одной стадии может быть несколько джоб, выполняющихся параллельно.

### Классическая цепочка стадий в Docker-мире:
1. **Build (Сборка):** Робот скачивает код и собирает Docker-образ по инструкции из `Dockerfile`.
2. **Test (Тестирование):** Внутри собранного образа или во временном контейнере запускаются автотесты (например, `pytest`).
3. **Deploy (Выкатка/Деплой):** Готовый и проверенный образ отправляется на боевой сервер и перезапускается в контейнере.

## 3. Основные инструменты CI/CD
На рынке существует множество систем автоматизации. Самые популярные из них:
* **GitHub Actions:** Прямо встроен в GitHub. Не требует ввода карт для бесплатного тарифа. Сценарии пишутся в файлах `.github/workflows/*.yml`. Основной стандарт для open-source.
* **GitLab CI/CD:** Мощный инструмент, глубоко интегрированный с репозиториями GitLab. Сценарии описываются в файле `.gitlab-ci.yml`. Требует верификацию картой в облачной версии для защиты от криптомайнеров.
* **Jenkins:** Старый, классический инструмент "селф-хостед" (устанавливается на собственный сервер). Сверхгибкий благодаря тысячам плагинов, но сложен в настройке.

## 4. GitLab CI и первые пайплайны
В GitLab конвейер настраивается через единственный файл `.gitlab-ci.yml`, который лежит в корне проекта.

### Пример синтаксиса эталонного файла:
```yaml
stages:
  - build
  - test
  - deploy

build-app:
  stage: build
  image: docker:latest
  script:
    - docker build -t myapp .

test-job:
  stage: test
  image: python:3.12
  script:
    - pip install -r requirements.txt && pytest

deploy-job:
  stage: deploy
  image: alpine:latest
  script:
    - docker run -d -p 3000:3000 myapp
```

### Важные правила YAML для VS Code:
* Отступы делаются **строго пробелами** (обычно по 2 или 4 пробела). Использовать клавишу `Tab` запрещено — пайплайн выдаст синтаксическую ошибку.
* Символ `&&` позволяет объединять команды в одну строку (например, установить зависимости и сразу запустить тесты). Вторая команда выполнится только если первая завершилась успешно.

## 5. Стратегии деплоя
Когда проект обновляется, нельзя просто выключить сайт на полчаса. Используются умные стратегии выкатки кода без остановки сервиса (Zero Downtime):

### Поочередное обновление (Rolling Update)
Фокус на **инфраструктуре**. Контейнеры на сервере заменяются по одному.
* *Схема:* Есть 4 контейнера версии v1. Робот удаляет первый, ставит на его место v2, ждет статуса `Up`, затем переходит ко второму.
* *Плюс:* Сайт не отключается ни на секунду.

### Канареечный деплой (Canary Deployment)
Фокус на **трафике и людях**. Новая версия выкатывается параллельно старой для жесткого тестирования.
* *Схема:* Рядом со старыми серверами запускается один контейнер v2. Балансировщик сети настраивается так, чтобы пускать туда всего **5% случайных пользователей**.
* *Плюс:* Если в коде есть баг, пострадает лишь 5% людей. Если за пару дней логи чистые — трафик плавно повышают до 100%.
